# Image prompt-injection in email

Benchmark for prompt injection carried **inside an image delivered in an email**
and ingested by a vision-capable email agent. The malicious content is
prompt injection (an instruction that tries to hijack the agent), not phishing.

All cases are wrapped as the **`image_attachment`** email surface in v1
(HTML-embedded surfaces — `cid:` / `data:` URI / text-image mismatch — are a
planned extension of `build.py`).

## Sources (see also `../../sources/NOTES.md`)

Per-record provenance is in `manifest.jsonl` (`provenance.source`,
`provenance.base_payload_id`). The dataset is a **hybrid** of three sources:

| `provenance.source` | Origin | License | Committed? |
|---|---|---|---|
| `cyberseceval3-visual-pi` | [facebook/cyberseceval3-visual-prompt-injection](https://huggingface.co/datasets/facebook/cyberseceval3-visual-prompt-injection) (Meta, PurpleLlama) — 1,000 PNGs with an instruction rendered into the image | **MIT, evaluation-only** (dataset card: "should not be used to train models") | **No** — `build.py` re-downloads to the gitignored `cache/`; used as a held-out test set only |
| `pdf-rasterized` | our `prompt-injection/*_pdf_attachment.eml` PDFs, rasterized to a page image with `pdftoppm` @150dpi (upstream: InjecAgent / AgentDojo / LLMail-Inject) | inherits upstream **MIT** | regenerated |
| `benign-rendered` | our `prompt-injection/benign/` email bodies rendered to a document-style image (FPR negatives) | project dataset license | regenerated |

⚠️ **CyberSecEval3 is evaluation-only and not redistributed.** We commit only
`build.py` (which re-derives it) and the text `manifest.jsonl` — never the PNGs.

## Contents

- `build.py` — deterministic generator (CyberSecEval3 wrap + PDF rasterize + benign render + `tesseract` OCR).
- `manifest.jsonl` — one harness-compatible `EmailRecord` per `.eml`.
- `cache/`, `assets/`, `eml/` — **gitignored**; regenerated by `build.py`.

Each positive carries two OCR signals in `source_metadata`:
- `payload_present` — the injected instruction is genuinely in the image (ground truth; CyberSecEval3 `image_text` or rendered text).
- `ocr_recovered` — naive `tesseract` recovered it. The gap between the two is itself a result: stylized in-image text defeats an OCR→text-detector front-end, so only a native vision model catches those.

Cross-modal: `pdf-rasterized` records share `base_payload_id` (`pi_XXXX`) with
the text/PDF surfaces in `../manifest.jsonl`, enabling a same-payload
text-vs-image detection comparison.

## Regenerate

From the repo root (full build pulls the 1.27 GB CyberSecEval3 download):

```bash
python3 dataset/prompt-injection/image-pi-email/build.py \
  --cse-limit 1000 --pdf-limit 347 --benign-limit 200
```
